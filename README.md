# Blessing of Pandora 模组简介

## 模组定位

**潘多拉之祝**（英文名：Blessing of Pandora）是《潘多拉之咒》的附属模组，模组 ID 为 `blessingofpandora`。模组将潘多拉之咒中的七个现实诅咒分别反转为七种理想祝福，并使用潘多拉之咒自带的潘多拉手环作为序诗与终章载体。

当前正常开发版本为 **1.7.3fix（女仆注入兼容与爱恋补领修复）**。七个祝福保留对应现实诅咒的正面效果，排除攻速/攻击距离/生命上限限制、低饱食度惩罚、恐惧禁攻、重复攻击衰减与附魔过载。第六祝福新增连击增伤与伤害保底，第七祝福新增按装备附魔等级计算的减伤；第三祝福不再提供幸运 +10，第四祝福不再提供强壮 +0.5。

## 环境与前置

- Minecraft：1.20.1
- Forge：47.4.10 或更新版本（最低要求）
- 潘多拉之咒：`curseofpandora >= 2.4.26`，必装
- Curios：`curios >= 5.4.5`，必装
- JEI：可选，15.20.0.106 或更新版本，用于实时查看七个诅咒的反转方式
- Touhou Little Maid：可选，1.5.3 或更新版本，用于爱恋宝珠与女仆适配

## 爱恋宝珠（可选车万女仆联动）

安装车万女仆 1.5.3+ 时才注册「爱恋」`blessingofpandora:love_orb` 与其进化宝珠「永生不悔·此生难忘」`blessingofpandora:eternal_love_orb`。宝珠使用原版物品模型和少色玫瑰粉像素纹理。首次自然驯服女仆时，自动保存她的身份；当时佩戴潘多拉项链便立即获得爱恋，否则之后戴上项链时自动补发，仍永久绑定最初的女仆。每位玩家仅一次，无法更换绑定；转移主人不算首次自然驯服，死亡或重新登录保留待领记录。

旧版存档中已错过爱恋、没有保存首位女仆身份且没有已有绑定的玩家，可佩戴潘多拉项链，潜行右键自己选定的已有女仆，补领一次并永久绑定她。旧版没有保存的历史身份无法自动推断，故此补救由玩家选择。已领取、已有绑定或因违誓永久损毁的玩家不能补领。

两颗宝珠的名称采用粉色流动亮纹与柔和光晕，参考 [The Long Travail](https://github.com/3101516445z-dotcom/The-Long-Travail) 的名称材质；物品提示和缓存的聊天名称都会持续流动，不需要安装该模组。

鼠标悬停在爱恋或「永生不悔·此生难忘」上，长按任一侧 Alt 约 0.5 秒，即可打开独立的玫粉色 HUD，提示下方细条显示按住进度。松开、移开鼠标或窗口失焦会取消打开。页面显示实际佩戴状态、永久绑定、七项约定的服务端实时进度、共享范围与惩罚规则；完成进化时自动切换为七项能力页面，也可切回查看约定。宽窗口采用双栏，窄窗口采用单栏，滚轮可查看全部内容；Esc 或关闭按钮返回原界面，不关闭原背包或饰品容器。物品悬浮提示保留摘要、绑定和 Alt 提示，完整说明收纳到 HUD。

把爱恋放入实际佩戴的潘多拉串饰栏位（包含项链和手环内部的继承串饰栏位）后，已加载的自有女仆共享这些栏位中已适配的宝珠、诅咒、祝福及套装串饰效果。主人需要在线且存活；共享不要求同维度，普通爱恋不主动加载女仆所在区块。进化宝珠另有绑定女仆区块强载能力，详见下表。背包、装饰栏、主人盔甲及其他非潘多拉饰品栏不属于共享来源。多个爱恋不会重复叠加一条共享链路；原模组允许多戴的属性串饰仍按合法数量累计。

采用真实女仆实体的属性与攻防事件，不把女仆伪装成玩家，不复制物品，不注册额外饰品槽。女仆使用自己的攻击目标、装备附魔与冷却；第七祝福计入女仆自身装备和共享串饰的有效附魔。玩家饥饿值、槽位扩容、反转/经验吸收/操作界面、客户端自动攻击、需要玩家能力的联动效果，以及未审计的第三方饰品回调在共享黑名单中。七个祝福的现实指数与魔力耐性可共享，精神/强壮的玩家饥饿机制不共享。

共享快照按主人复用，饰品变化事件触发刷新，另以错峰的 10 游戏刻周期兜底检查内部物品变化；常规延迟至多约 0.5 秒。快照不变时不会重复复制物品或重加静态属性。战斗状态归女仆独立维护，附近实体查询仅在实际技能触发时进行。卸下共享宝珠、主人离线/死亡及女仆所有权变化会结束对应共享；不使用反射。

完整的 84 项原模组饰品及七祝福审计、共享范围和分项黑名单见 [爱恋兼容清单](validation/1.7.3/love-research/pandora-audit.md)。

### 永生不悔·此生难忘

爱恋完成七项约定后自动转化。进化宝珠在潘多拉串饰栏位有效佩戴时提供以下七项能力。原饰品共享仍覆盖符合条件的自有女仆；其余新增能力只作用于主人和永久绑定的第一位女仆，不会赋予其他女仆。

| 佩戴能力 | 效果 |
| --- | --- |
| 其一·爱恋 | 保留爱恋原有的安全饰品共享效果与黑名单。 |
| 其二·永生 | 主人与绑定女仆受到致命伤时回满生命；双方各自冷却 60 游戏刻（正常 20 TPS 下为 3 秒）。 |
| 其三·不悔 | 主人对绑定女仆的攻击完全无效，不触发女仆的受攻击效果。 |
| 其四·此生 | 双方获得创造飞行；主人飞行时，绑定女仆跟随并保持在 8 格内。 |
| 其五·不忘 | 保持绑定女仆当前区块加载；离开的旧区块默认保留 600 游戏刻（正常 20 TPS 下为 30 秒）的缓冲。 |
| 其六·一生一世 | 双方造成的伤害增加 1314%，即原伤害的 14.14 倍。 |
| 其七·爱 | 双方有效护甲固定为 520；不清除盔甲或原有属性，卸下后恢复原护甲。该数值是护甲值，不是 520% 减伤。 |

卸下、离线、退化或永久损毁时，进化能力与本宝珠添加的区块强载立即撤销，不继续保留旧区块缓冲。原有创造/旁观模式的飞行能力不会被夺走。重复佩戴不会重复叠加上述能力，卸下重戴也不会重置「其二·永生」的冷却。

进化进度只认永久绑定的第一位女仆：

| 约定 | 条件与规则 |
| --- | --- |
| 其一·永恒 | 在潘多拉串饰栏位佩戴爱恋，累计游玩时间达到 24 小时。 |
| 其二·恒久 | 绑定女仆从未真正死亡；死亡记录永久保留，复活或清零进度也不会清除。 |
| 其三·历战 | 佩戴期间，绑定女仆累计造成至少 1,314,520 点实际生命伤害；其他女仆、被抵消或超出目标剩余生命的伤害不计入。 |
| 其四·智力 | 佩戴期间，玩家与绑定女仆对战五子棋、中国象棋、国际象棋，各获胜一次。 |
| 其五·浪漫 | 佩戴期间，玩家与绑定女仆在同一维度且双方均处于繁花森林，累计游玩时间严格超过 30 分钟。 |
| 其六·酸涩 | 首次佩戴后驯服其他女仆，清零佩戴时间、伤害、棋局胜利、浪漫时间与誓言；已进化宝珠退回爱恋，绑定与死亡记录不变。 |
| 其七·誓言 | 佩戴时发送同一条聊天消息，包含「女仆」与「我爱你」且无禁用词。首次佩戴后，消息同时包含「女仆」与任一禁用词，会使宝珠永久损毁并禁止该玩家再次获得两种宝珠。 |

时间按实际游戏刻累计，离线或卸下时不增长；物品提示中可查看各项进度。**酸涩和违誓惩罚从首次佩戴起持续生效，临时卸下、重新登录或完成进化都不能豁免。** 违誓后的创造模式物品与掉落物也会被销毁，重新获得物品不会恢复资格。创造模式复制品不能凭空建立新的第一女仆绑定。

禁用词完整列表为：`不`、`讨厌`、`恨`、`厌恶`、`憎恶`、`嫌弃`、`恶心`、`去死`、`滚`、`讨嫌`、`烦人`、`垃圾`、`贱`。判定针对同一条聊天消息做字面匹配，忽略空白与不可见格式字符，不理解句意；**「女仆，我不会离开你」这类正面表达也会因含有「不」而触发永久损毁**。禁用词优先于「我爱你」的誓言判定。

## 七个理想祝福

佩戴且满足归属要求时，七个祝福提供以下效果。每个祝福额外提供 **+1 魔力耐性**，用于减轻仍然佩戴的第七诅咒所产生的附魔过载。

| 祝福 | 效果 | 现实指数 |
| --- | --- | --- |
| 理想第一祝福：自由 | 攻击速度不高于 0.5 时获得 +100% 攻击速度；+1 项链饰品栏位 | +1 |
| 理想第二祝福：无限 | 攻击距离不高于 2.0 时获得 +50% 攻击距离；+1 手镯饰品栏位 | +1 |
| 理想第三祝福：精神 | 饱食度至少为 14 并持续 2 分钟后获得 +100% 最大生命值；+1 通用饰品栏位 | +1 |
| 理想第四祝福：强壮 | 现实指数至少为 5 时，超过 16 的每点饱食度提供 +5% 攻击伤害和移动速度，满饱食度额外 +20%；满饱食度抵消移动速度属性减益 | +1 |
| 理想第五祝福：无畏 | 命中目标放置标记，10 秒后成熟，随后 10 秒内每层对该目标 +20% 伤害，最多 5 层；+1 手饰饰品栏位 | +2 |
| 理想第六祝福：安魂 | 2 秒内连续伤害同一目标，每个已有连击层 +10% 伤害，最多 +50%；单次伤害保底目标最大生命的 0.5%；+3 护符饰品栏位 | +1 |
| 理想第七祝福：解脱 | 装备的有效附魔总等级每级提供 0.2% 减伤，最多 80%；+1 手饰饰品栏位 | +1 |

第一、第二祝福判断阈值时不计入自身奖励，避免奖励生效后反复开关；其它装备和效果的加成保留。第三祝福饱食度低于 14 后重置计时并移除自己的生命奖励。第四祝福在现实指数满足条件且满饱食度时，攻击伤害和移动速度总共增加 40%；低饱食度不会施加惩罚。抵消满饱食度下的负移速属性不需要现实指数达到 5，但不改变蛛网等不通过属性实现的环境减速。

第五祝福的标记不会因为玩家受到攻击而清除，也不会禁止反击。第六、第七祝福的新动态效果属于本模组设计，不是潘多拉之咒的原始正面效果。

第六祝福在实际造成正生命伤害后为该目标建立连击层，因此首击没有连击增伤。之后 2 秒（40 游戏刻）内再次伤害同一目标，每个已有层数提供 +10% 伤害，最多 5 层、合计 +50%；成功命中续期，超时清除。护甲、魔法和吸收结算后仍有正生命伤害时，先将其保底为目标最大生命的 0.5%，再结算目标第七祝福减伤。被取消、归零或完全被吸收的攻击不触发保底，也不增加或刷新连击。

第七祝福逐件统计主手、副手、盔甲和实际佩戴的 Curios 饰品，包含潘多拉内部饰品；背包和装饰栏位不参与。普通附魔与诅咒附魔都按有效等级相加，同一件装备上的同一种附魔只计一次，无效附魔和假闪光不计。每级减免剩余生命伤害 0.2%，400 级达到 80% 上限；这项减伤不降低吸收值的消耗。

第三祝福的连续饱食计时和成熟后的生命上限随存档保存，重登和跨维度不会使已获得的生命奖励消失；卸下、失去归属、饱食度不足或死亡时清除。最大生命增加不会直接治疗。第五祝福的标记为临时状态，在卸下、失去归属、死亡、退出或跨维度时清除。第三、第四的饱食度效果仅用于拥有饱食度的玩家。

祝福效果采用本模组 1.6.0 固定数值：原有效果参考潘多拉之咒 2.4.26 默认值，第一祝福使用 +100% 攻速，第六、第七新增效果采用上述本模组设计。修改潘多拉之咒自身配置不会改变上述祝福数值；反转条件仍由 `blessingofpandora.toml` 控制。

`blessingofpandora:strong` 属性及其处理逻辑为旧存档兼容继续保留，但第四祝福不再授予这一属性。

## 潘多拉手环与诅化祝

- 玩家第一次同时佩戴七个现实诅咒时，会获得带有“序诗” NBT 的潘多拉之咒手环（`pandora:pandora_bracelet`）。
- 玩家每将一个身上的诅咒转化为祝福，“诅化祝”数值增加 1。
- “诅化祝”初始值为 0，上限为 7。
- 数值第一次达到 7 时，会获得带有“终章” NBT 的潘多拉之咒手环，之后数值不再变动，也不再重复检测。
- 两种手环都会记录获得玩家，只有该玩家可以装备。

## 开局赠送配置（1.5.2）

配置文件为 `config/blessingofpandora.toml`，全部配置项均附有中文注释。以下两个开关默认均为 `true`：

| giveStartingNecklace | giveStartingCurses | 开局奖励 |
| --- | --- | --- |
| true | true | 潘多拉项链，内含七个现实诅咒（前置模组默认行为） |
| false | true | 直接获得七个诅咒物品，不赠送项链 |
| true | false | 空的潘多拉项链 |
| false | false | 不赠送项链和诅咒 |

开关沿用前置模组的一次性进度奖励，只影响尚未领取开局奖励的玩家。修改不会删除已获得物品，也不会在重登或死亡重生时补发。单人使用本地配置，联机使用服务端配置；建议修改后重启。诅咒直接给予玩家时为物品，不会自动装备。

这两个开关自 1.5.2 加入，1.6.0 继续保留。

## 游戏内指令

以下指令需要管理员权限，并且默认关闭。需要将 `config/blessingofpandora.toml` 中的 `enableCommands` 改为 `true` 并重启后才会注册。

直接转化身上对应的诅咒：

```mcfunction
/blessingofpandora 1
/blessingofpandora 2
/blessingofpandora 3
/blessingofpandora 4
/blessingofpandora 5
/blessingofpandora 6
/blessingofpandora 7
```

数字对应：1 自由、2 无限、3 精神、4 强壮、5 无畏、6 安魂、7 解脱。转化后的祝福归属当前玩家。

赐予祝福物品：

```mcfunction
/blessingofpandora give freedom
/blessingofpandora give freedom @p
/blessingofpandora giveall
/blessingofpandora giveall @p
/giveblessing freedom
/giveblessing freedom @p
```

可补全名称：`freedom`、`infinity`、`spirit`、`strength`、`fearlessness`、`requiem`、`liberation`。

## 反转控制 HUD

- 潜行右键潘多拉项链或潘多拉手环可以打开全局反转 HUD；按下默认按键 P 也可以打开。
- 全局 HUD 会列出七个祝福，并显示对应的当前反转条件。
- 每个祝福都有独立的允许/禁止按钮，可以直接切换对应诅咒是否允许自动反转。
- 潜行右键任意一个现实诅咒物品，会打开只对应这个诅咒的反转允许/禁止 HUD。
- HUD 会随窗口大小自适应排版，小窗口时自动换行并可纵向滚动，内容不会超出边框。
- 潘多拉项链、潘多拉手环和七个诅咒物品的描述底部都会显示“潜行+右键查看反转方式”。
- HUD 与 JEI 的反转说明均从 `config/blessingofpandora.toml` 读取可配置数值，不硬编码默认条件。
- 第一、第五诅咒的各处反转说明显示当前击杀转化概率；失败后实时提高，成功后恢复基础概率。
- 第七诅咒会额外显示当前佩戴物品上的诅咒附魔数量，以及按该数量实时计算的实际转化概率。
- 第六诅咒的 HUD 与 JEI 描述会显示当前已吸收经验点数，并随服务器吸收进度实时更新。
- HUD 与 JEI 中可通过配置修改的数值使用黄色加粗强调，第七诅咒实时附魔数量和实际概率使用青色加粗强调。
- 潘多拉之祝转化调试棍的合成配方已移除；创造模式玩家或管理员手持调试棍时，右键可打开独立的“直接转化”HUD。服务端会再次校验权限与手持物品，只能还原自己的或无主的祝福。
- 联机时 HUD 和 JEI 使用服务器同步的反转配置；配置重载后在线玩家会收到更新。1.7.3 新增爱恋进度同步，客户端和服务端须使用相同版本，确保协议与显示一致。

## 车万女仆适配

安装了 Touhou Little Maid 后，女仆也可以通过 Curios 佩戴潘多拉串饰中的祝福物品。女仆获得固定饰品栏位、现实指数和魔力耐性时会检查女仆主人是否与祝福归属玩家一致：

- 主人一致：女仆可以获得上述固定栏位和属性奖励。
- 主人不一致或女仆没有对应主人：这些效果不会触发。

未记录归属的祝福属于无主版本，玩家和女仆都可以正常使用。

## 塑魂

- 新增药水效果“塑魂”（`blessingofpandora:soul_sculpting`），不添加对应药水瓶等物品。
- 身上同时拥有至少 10 种其它药水效果时自动获得塑魂；正面、负面和中立效果均计入，同一种效果无论等级只计一种，塑魂自身不计入。不足 10 种时立即消失。
- 拥有塑魂期间，实体获得 20% 最大生命值提升，并受到 20% 额外伤害。最大生命提升作用于原版最大生命属性，额外伤害通过本模组注册的 `soul_sculpting_damage_taken` 受伤倍率属性结算。

## 诅咒反转

玩家需佩戴对应诅咒并允许其自动反转。七个现实诅咒分别拥有独立的反转条件：

- 现实第一诅咒：囚笼 → 自由：你或你的仆从击杀凋零，初始概率 20%；每次失败增加 10 个百分点，最高 100%。当前概率见游戏内反转说明。
- 现实第二诅咒：制限 → 无限：在主世界从 Y=666 及以上下落到 Y=-60 及以下。
- 现实第三诅咒：血肉 → 精神：获得隐身效果后被闪电击中。
- 现实第四诅咒：羸弱 → 强壮：你或你的仆从击杀生命上限不低于 325 且带有虚弱效果的生物。
- 现实第五诅咒：恐惧 → 无畏：你或你的仆从击杀坚守者，初始概率 20%；每次失败增加 10 个百分点，最高 100%。当前概率见游戏内反转说明。
- 现实第六诅咒：碎魂 → 安魂：获得塑魂效果后，极快吸收自身经验，累计吸收 2,000,000 点。效果中断时已吸收进度保留。
- 碎魂按等级与经验条计算可用经验，最多每刻吸收 50,000 点且不超过剩余需求；进度随玩家保存，重启后保留，取下对应物品时仍按原规则重置。
- 现实第七诅咒：咒缚 → 解脱：每游戏刻有 0.0001% 概率自动转化；物品上每拥有一个诅咒附魔，额外增加 0.0005% 每游戏刻转化概率。

第一、第五诅咒分别使用 `[reversal_first]` 与 `[reversal_fifth]` 的 `mob`、`baseChancePercent`、`failureBonusPercent` 配置。当前概率为 `min(100, 基础概率 + 失败次数 × 失败增量)`，单位为百分比；例如默认失败两次后，下次概率为 40%。卸下、死亡、重登后失败次数保留，成功反转后重置对应计数。未佩戴、禁止反转或击杀不匹配的生物时，不进行随机判定，也不增加失败次数。旧配置中的第一诅咒 `buff`、`requireEmptyHands` 和第五诅咒 `heldItem` 不再使用。

配置文件位于游戏目录的 `config/blessingofpandora.toml`；联机修改服务端文件。配置加载后，判定与游戏内说明使用同一组数值，现有失败次数按新概率参数重新计算。运行中重载成功时会同步在线客户端；Forge 所用的 NightConfig 3.6.4 在 Windows 下可能漏掉合并的文件保存通知，因此不能保证每次保存都会立即热重载。停服修改后重新启动可可靠生效，单人游戏则完全退出游戏后修改并重新启动。第一、第五在游玩过程中因击杀而变化的概率仍会即时同步，不依赖文件监听。

目标必须是已注册的生物 ID，或 `any`。不存在的 ID 保留原文显示且不触发反转。

第一、第四、第五诅咒的击杀判定会沿致命伤害来源的主人关系查找玩家，支持车万女仆、驯服生物，以及通过标准 `OwnableEntity` / `TraceableEntity` 接口提供归属的召唤物和弹射物；另对 Iron 的法术与魔法书召唤物、新生魔艺魔宠提供专门适配。主人仍需佩戴对应诅咒并允许自动反转；成功转化、进度和成就均归主人。每次有效死亡对每项条件只判定一次，无法识别归属的伤害不会猜测主人。其它使用模组私有归属机制的仆从可能需要额外适配。

转化完成后，祝福会归属转化玩家；生存模式下也可以正常取下。转化时会在物品栏上方显示 8 秒提示。

“诅化祝”计数在死亡重生后继承。已领取终章但旧版计数丢失的玩家会恢复到 7，不会重复领取手环。自定义 4,000,000 点经验门槛和 `minecraft:pig` 目标不再被强制覆盖。

## 潘多拉诅咒附魔书

潘多拉诅咒沿用宝藏诅咒附魔的生成规则，可以出现在允许相应随机附魔的战利品箱装备上。将带有潘多拉诅咒的装备与普通书分别放入砂轮两个输入格，取出结果即可获得一本潘多拉诅咒附魔书。

取出结果时消耗一本普通书，清除原装备上的全部存储附魔（包括其他诅咒）并重置附魔修复惩罚；装备保留在原输入格，耐久、名称和其他数据保留。上下格顺序不限，取消操作不改变装备。此转移不额外返还经验，也不提取物品固有的动态附魔。
